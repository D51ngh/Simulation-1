Chapter 1

A qubit, its phase, and the wrong rotation

Picture the qubit as an arrow pointing from the centre of a globe to its equator. We start it at the point called |+⟩ (“fine”). The opposite point, |−⟩, means “flipped”.

A transmon has a natural frequency, so its arrow spins around the equator all the time. That spin is correct: we know its rate exactly, so it is not an error. Noise from the environment (magnetic flux, stray charges, nearby circuits) nudges the frequency by a small amount δω. Now the qubit spins slightly too fast or too slow, and drifts away from where it should be. That drift is the phase error θ:

θ = ∫ δω(t) dt   ·   the frequency error added up over time

Physicists usually “ride along” with the correct spin, like standing on a merry-go-round. In that rotating frame the correct arrow stands still and only the wrong extra rotation is visible.

Our noise model

We describe δω with an Ornstein–Uhlenbeck (OU) process: noise that wanders randomly but remembers its recent past. It has two knobs: the correlation time τc (how long the noise remembers itself) and the strength V (how big the wobbles are). In the thesis we keep V fixed and sweep τc, so any change we see comes from the noise's memory alone.

Takeaway: noise changes the qubit's frequency; added up over time, that makes it rotate by an extra angle θ beyond its correct, known spin.

Chapter 2

A tilt is a mix of “fine” and “flipped”

This is the single most important idea. A qubit tilted by θ is exactly a combination of the fine state |+⟩ and the flipped state |−⟩: one state, written two ways.

tilted qubit = cos(θ/2) |+⟩ − i sin(θ/2) |−⟩

The two numbers say how much of each piece is present. Squared, they are probabilities: a check finds the qubit “fine” with chance cos²(θ/2) and “flipped” with chance sin²(θ/2).

Chapter 3

The stabilizer check, step by step

We never look at the data qubit directly. A helper qubit, the ancilla, does the checking. One check is called a round.

  1. Reset the ancilla to |0⟩, then a Hadamard gate turns it into |+⟩.
  2. CNOT between ancilla and data. Flipping |+⟩ changes nothing; flipping |−⟩ adds a minus sign, which “kicks back” onto the ancilla. So the fine piece of the data tags the ancilla 0, the flipped piece tags it 1.
  3. A Hadamard, then measure the ancilla. Reading a tag always gives one answer, never “mostly 0”.
  4. The piece whose tag did not come up is gone. The data qubit is now exactly |+⟩ or exactly |−⟩: the tilt has been erased. It only decided the odds.

Each answer is a syndrome s (0 = fine, 1 = flipped). A detection event d marks a round where the answer changed: d = sthis round ⊕ slast round. Detection events are all a decoder ever sees.

1.0×

One shot vs many shots. One run (a shot) gives only yes/no per round, so it cannot tell you how much phase built up. Repeat the experiment many times and count how often each round fires: that fraction f estimates sin²(θ/2), so θ = 2·arcsin√f recovers the hidden phase of each window. You lose the sign (too fast and too slow look the same), and it breaks down as f approaches 50%.

Takeaway: the CNOT tags the “fine” and “flipped” pieces; reading the tag keeps one and erases the tilt. Detection events record when the answer changed, and many shots recover the phase per window.

Chapter 4

Measuring often: phase does not pile up

Continuous noise keeps acting, but every check resets the tilt to zero. The qubit only ever carries the phase picked up since its last check.

Because the flip chance grows like the square of the tilt, cutting the same total phase into many small, separately checked pieces makes flips much rarer. This is the quantum Zeno effect.

So how long until the check notices the noise?

This is the central quantity of the project, the detection latency: the time from when noise switches on (here at 0.3 µs) to the first detection event. Chapter 5

Four data qubits and the gate schedule

In a surface code each stabilizer checks the joint parity of four data qubits. Its ancilla does four CNOTs one after another, on a fixed clock, every round.

The check “looks at” each qubit only during that qubit's CNOT. An error that arrives just after its qubit's CNOT is missed this round and caught next round. Pick a qubit and a time, press play, and watch.

Simplification: in a real surface code the four data qubits share an entangled state. Treating each separately gives the correct timing of when the stabilizer fires.

With the defaults, Q1 is hit at 200 ns, just after its CNOT ended at 180 ns, so it is caught in round 2. The same hit on Q2, Q3 or Q4 is caught in round 1. Same moment, different qubit, different round. This gate-scheduling effect can make two simultaneous errors look like noise travelling from one qubit to another, which is exactly what a timing-aware decoder must not be fooled by.

Takeaway: detection latency = waiting for the next CNOT + waiting for the readout. Which round an error appears in depends on when it hits, which qubit it hits, and how strong it is.

Chapter 6

The decoder: minimum-weight perfect matching

The distance-3 surface code stores one protected qubit in nine data qubits (Q1–Q9). Purple X checks catch Z errors. When checks fire, the decoder has to guess which qubits flipped.

Every data qubit is a link between the checks it touches (or between a check and an edge of the code). Each fired check must be paired with another fired check or with an edge. MWPM picks the pairing that needs the fewest flipped qubits, the most likely explanation when errors are rare. The correction is usually just recorded in software (the Pauli frame) and applied when the qubits are finally read.

In You be the decoder the errors are hidden; you see only what a real decoder sees.

Beyond this demo. Real decoders match in space and time: detection events from different rounds are nodes too, and edges also connect rounds (for measurement errors and for errors delayed by the gate schedule). Standard MWPM gives every edge the same kind of weight, ln((1−p)/p), assuming errors are independent.

Takeaway: the decoder sees only fired checks, picks the least-weight explanation, and tracks the correction in software. It fails when the true errors are less likely than another explanation.

Chapter 7

The thesis: how much noise memory reaches the decoder?

Everything above is one chain. The research asks how much of the noise's physical memory survives each link, and whether a decoder can use it.

Three memory times

NameMeaningWhere you met it
τ_environment (τc)How long the noise remembers itselfChapter 1, the OU model
τ_qubitHow long that memory stays in the qubit's phaseChapters 1–2
τ_syndromeHow much memory survives into the detection record, after checks reset the tilt every roundChapters 3–5

What to watch out for

A late detection does not always mean the noise arrived late. Gate scheduling (Chapter 5), measurement errors, slow phase build-up (Chapter 4), one error firing two checks, and errors cancelling each other can all make the detection record look correlated when the noise is not. The simulator therefore keeps the hidden truth (noise onset, true phase, true flips) separate from what a decoder sees, so every inference can be checked against the answer.

The thesis in one sentence: how much of the noise's physical memory survives through the transmon and the stabilizer circuit into the syndrome record, and can a decoder use it to correct errors better?
