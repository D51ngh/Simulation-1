Why this matters

Quantum computers make mistakes because their hardware is noisy. Quantum error correction protects information by spreading one logical qubit over many physical qubits and checking them over and over with stabilizer measurements. A decoder reads the results of those checks and works out which correction to apply.

Most decoders are built on a simplifying assumption: errors in one round have nothing to do with errors in the next. Real superconducting qubits don't quite work that way. Their frequency drifts because of flux noise, charge noise and two-level defects (TLS), and that drift can last for microseconds, which is many rounds of error correction. In other words, the noise has memory.

Research question: how much of the noise memory survives through the qubit and the stabilizer circuit into the syndrome record, and can a decoder use it to reduce logical errors?
2

The model, one link at a time

I follow the noise through every step from the physical environment to the decoder:

OU noise δω(t) → H(t) = ħδω(t)Z/2 → phase θ = ∫δω dt → Z error, P = sin²(θ/2) → syndrome → detection event → decoder

The frequency noise is an Ornstein–Uhlenbeck (OU) process, dξ = −(ξ/τc)dt + σdW, whose correlation time τc sets how long the noise "remembers" its past. Each stabilizer check projects the accumulated phase tilt θ into either "no error" (probability cos²(θ/2)) or a full Z flip (probability sin²(θ/2)). A detection event is a change in the check result between rounds, dr = sr ⊕ sr−1.

That gives three memory times to track:

Time scaleMeaning
τenvironment (τc)How long the noise itself stays correlated
τqubitHow long that history remains in the qubit's phase
τsyndromeHow much correlation is left in the detection events after repeated measurement

The decoder only ever sees τsyndrome, so the first task is to measure how τc maps onto it.

3

What I built

To build intuition and test each link before scaling up, I wrote three tools that run in the browser or in Python:

ToolWhat it does
Interactive walkthroughSeven steps from a single qubit's phase to a distance-3 surface code with a minimum-weight perfect matching (MWPM) decoder, each with a live simulation.
Simulation LabA weight-4 stabilizer with adjustable noise (steady or OU), spreading between qubits, and gate timing. It records detection probability, detection latency and the full syndrome history over many shots, with CSV export.
QuTiP cross-checkEvolves a data qubit under H(t) with QuTiP and checks that the phase recovered from the quantum state matches the analytic model (they agree to 0.01°).

Throughout, the simulation keeps the true noise history separate from what a decoder can see, so every inference can be checked against ground truth.

A worked example

Here is one run of the QuTiP simulation: a strong, TLS-like burst of OU noise (140 kHz peak, τc = 2 µs) that starts at 0.3 µs and lasts 7 µs, checked by an X stabilizer once every 1 µs for 8 rounds.

10.0°0.00+1—
299.3°0.58−1Yes
3108.5°0.66−1—

5–8below 16°≤ 0.02−1—

What this shows. The noise lasted about 7 µs, but in this shot it left just one detection event. After the first flip the qubit stays flipped, and the strong phase in rounds 3 and 4 happened not to flip it back. Whether it does is random, which is exactly why a single shot can hide the noise's memory and why the Lab collects statistics over many shots. Telling these cases apart from independent noise is the core of what a correlation-aware decoder would need to do.

Where this is going

The work is organized as a ladder of experiments, each adding one ingredient:

StageSetupPurpose
P0No noiseControl: no detection events
P1Single Z error at a set timeLatency from the gate schedule alone
P2Constant frequency offsetAdds phase build-up time
P3OU noiseEffect of noise memory on latency
P4Sweep cycle time T and τcFind where the behavior changes
P5Inference from many shotsRecover the phase per round
P6Distance-3 code with MWPMLogical error rate versus τc
P7Correlation-aware decoderTest whether noise-informed weights reduce the logical error rate

The interactive tools cover the single-stabilizer stages. The next steps are P6 and P7: full multi-round surface-code circuits in Stim, decoded with space-time MWPM in PyMatching, at distances 3, 5 and 7, first with standard weights and then with weights informed by the noise correlation time.

6

Limitations, stated plainly

This is a deliberately simple model so each link can be checked on its own. It uses a two-level qubit with noise entering only through a frequency shift. It does not yet include the multilevel transmon, T₁/T₂ decay, leakage, gate or measurement errors, or the shared entangled state of a real surface code. The MWPM decoder in the walkthrough is a one-round teaching example. Gate timings (1 µs cycle, 60 ns CNOT, 300 ns readout) are illustrative values, not measurements from a specific device.

About me

Why I'm working on this

I came to quantum computing from computer science and economics, after two years in industry building tools that automate tedious work. What drew me to error correction is that it sits right where physics, information theory and engineering meet, and that real hardware keeps breaking the tidy assumptions our models make. I built these tools partly to understand the problem myself and partly so others can see it too.

I'm applying to PhD programs in quantum error correction and fault-tolerant quantum computing for Fall 2027. If this work interests you, I'd be glad to hear from you: d51ngh.github.io · LinkedIn · GitHub.
